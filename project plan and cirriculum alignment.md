# Sovereign Shards: Project Plan & Curriculum Alignment

---

## Phase 1: Kickoff & Onboarding  
*Weeks 1–2*  
**Purpose:** Prepare contributors with tooling, workflow culture, and immediate onboarding success.

### Deliverables
- Repo cloned, setup script run
- Onboarding checklist completed
- “First win” validated
- Project Charter understood

### Key Roles
- Project Lead
- Faculty Mentor
- Onboarding Peers

### Tasks
1. Clone the repo, verify workspace setup (Python, scripts run successfully)
2. Read the Welcome & Project Charter
3. Complete first “win” ticket
4. Join kickoff call or team chat

### Curriculum/Learning
- Git/GitHub fundamentals
- ReadMe/Doc navigation
- Team etiquette

---

## Phase 2: Building & Shipping First Tools  
*Weeks 3–4*  
**Purpose:** Develop and submit first basic tools, reinforce safe and collaborative coding practices.

### Deliverables
- At least one new tool script per person in `tools/run/`
- Documentation/comments added
- All code passes lint and unit tests

### Key Roles
- Tool Developers
- Code Reviewer

### Tasks
1. Scaffold a basic script
2. Follow template and “Five Masters” style
3. Run local lint/ unit tests
4. Commit changes with standardized messages; open a Pull Request
5. Peer and faculty/AI review before merge

### Curriculum/Learning
- Python scripting, error handling
- Static analysis and code quality
- Issue tracking and PR flow
- Code review etiquette

---

## Phase 3: Core Architecture & Integration  
*Weeks 5–7*  
**Purpose:** Expand and solidify project infrastructure, demonstrate tool integration, document design choices.

### Deliverables
- Extension of ToolRegistry and core architecture
- Markdown docs and diagrams showing team workflow, system design
- Full test pass for all features

### Key Roles
- Group leads for Tools, Integration, Docs
- Ongoing Code Reviews

### Tasks
1. Design new tools; assign tickets
2. Implement integration (chaining tools, outputs)
3. Add or improve documentation
4. Run focused tests
5. Present work in midpoint review

### Curriculum/Learning
- Modular project-based Python
- System design and diagrams
- Documenting code/processes
- Testing strategies

---

## Phase 4: Advanced Teamwork & Scenarios  
*Weeks 8–10*  
**Purpose:** Simulate real-world engineering challenges—complex tasks, API/resources, teamwork.

### Deliverables
- Multi-step tool pipelines
- API/model integration demo (if resources granted)
- Written “postmortem” of challenges

### Key Roles
- Integration Engineers
- Project Manager
- QA Lead

### Tasks
1. Plan and build advanced scripts
2. Integrate API/model or document needs
3. Team challenges: merges, role-switching
4. Document and present learnings
5. Regular check-ins with mentor

### Curriculum/Learning
- Advanced Python/APIs
- Agile roles
- Debugging and documentation
- Teamwork skills

---

## Phase 5: Delivery, Reflection, Portfolio  
*Weeks 11–12*  
**Purpose:** Finalize and present the project; reflect, document, and celebrate outcomes.

### Deliverables
- Completed repo
- Demo (live/recorded)
- Learning reflections
- Faculty/AI retrospective

### Key Roles
- Documentation Lead
- Team Spokesperson

### Tasks
1. Prepare user and dev docs
2. Host/record project demo
3. Submit learning reports
4. Final retrospective
5. Archive and share artifacts

### Curriculum/Learning
- Documentation
- Presentation skills
- Reflection
- Building a portfolio

---

## Timeline/Flexibility
- Each phase is 1–2 weeks, flexible to team and calendar needs.
- Regular checkpoints with faculty/AI for accountability and curriculum alignment.
